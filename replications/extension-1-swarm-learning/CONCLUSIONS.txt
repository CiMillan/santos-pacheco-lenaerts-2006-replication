Why swarm optimization plateaus below imitation, instead of catching up
========================================================================
Finding from comparing compare_imitation_vs_swarm.py's two traces (see
imitation_vs_swarm.png): under the fixed PD (T=1.2, S=-0.1, R=1, P=0) on
scale_free, imitation climbs to ~90% cooperation while swarm settles into a
noisy plateau around ~30-35%, and does not improve from there even given
the same 360 generations. This is not a bug -- it's a structural mismatch
between how PSO remembers fitness and how a social dilemma's payoff
landscape actually behaves. Confirmed by instrumentation, not assumed.

THE MECHANISM
  PSO's "personal best" is a running maximum -- swarm_update_rule.py's
  cognitive term (see next_position()) always pulls an agent back toward
  the position that earned its single best-ever payoff. That memory can
  only be replaced by something even higher; it never decays and is never
  reconsidered.

  In this Prisoner's Dilemma (T=1.2 > R=1 > P=0 > S=-0.1), the single
  highest payoff any agent can ever earn is by DEFECTING against
  cooperating neighbors -- payoff.py sums T per cooperating neighbor a
  defector faces, so a well-connected node surrounded by cooperators can
  rack up a large one-off payoff. Mutual cooperation only ever earns R per
  neighbor, and R < T by the very definition of this game. So the ceiling
  any cooperator can ever reach is structurally lower than the ceiling a
  lucky early defector can reach.

  Positions start random (~50/50 C/D), so early on there are plenty of
  cooperators to exploit. 443/500 agents (89%) hit their personal-best
  payoff from a defect-side position, almost certainly in this early
  window -- mean personal_best_payoff (4.22) is roughly 7x the mean payoff
  anyone is actually earning by the end (0.61), meaning these are stale
  windfalls, not something currently being re-earned. From that point on,
  the cognitive term keeps pulling those agents back toward defection
  regardless of what's actually working in the population now.

WHY IMITATION DOESN'T HAVE THIS PROBLEM
  ../../update_rule.py's pairwise-comparison rule only ever compares THIS
  generation's payoff between two specific neighbors, and only copies if
  the other one is doing better right now. There is no persistent memory
  of an early lucky outcome -- it's fully reactive to the population's
  current state. That's exactly what lets network reciprocity work: a
  cluster of cooperators propping each other up can gradually win out over
  time, because nothing is permanently anchored to a one-off windfall from
  generation 3.

TAKEAWAY
  This is a genuine structural mismatch, not a tuning problem: PSO's
  memory-of-best-ever-fitness is built for static optimization landscapes,
  where the best point found is still the best point later. A social
  dilemma's payoff landscape is frequency-dependent -- the value of
  defecting depends on how many cooperators are left to exploit, which
  shrinks as more agents defect. "Best fitness ever observed" is a
  systematically bad target to chase in a landscape like that, and biases
  the swarm mechanism toward defection almost independently of the actual
  (T, S) dilemma strength.
