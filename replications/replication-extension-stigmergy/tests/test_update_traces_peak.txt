for p in [5, 0, 0, 0]:
    t = update_traces_peak(t, {0: p}, 0.2)
    print('peak, lam=0.2, payoff', p, '-> trace', round(t[0], 3))
"

Expected output (exact -- no randomness here):
average, lam=0.5: {0: 1.0, 1: 2.0}
peak,    lam=0.5: {0: 2.0, 1: 2.0}
peak,    lam=1  : {0: 2.0, 1: 0.0}
peak, lam=0.2, payoff 5 -> trace 5
peak, lam=0.2, payoff 0 -> trace 4.0
peak, lam=0.2, payoff 0 -> trace 3.2
peak, lam=0.2, payoff 0 -> trace 2.56

Why: the peak trace differs from the average trace only when the payoff
goes UP. Node 0 (trace 0, payoff 2): the average moves halfway to 1, the
peak jumps straight to 2. Node 1 (trace 4, payoff 0): both fade the same
way, to 2. With lam=1 both are just the current payoff (the paper's rule).
The last four lines are a one-off windfall of 5: the peak trace takes it in
full and then keeps 80% of it each generation (4.0, 3.2, 2.56) -- it
remembers a windfall the way PSO's personal best does, but slowly forgets.
A bug would show as the peak trace lagging behind a rise, or fading
differently from the average trace.
