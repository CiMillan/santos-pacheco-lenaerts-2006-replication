# Part 1: load_results() turns saved "T,S" string keys back into tuples
python3 -c "
from c1_zero_experiment import load_results
print(load_results({'1.5,-0.5': 0.2, '0.0,1.0': 1.0}))
"

Expected output:
{(1.5, -0.5): 0.2, (0.0, 1.0): 1.0}

Why: JSON can't store tuple keys, so topology_experiment.py saved them as
"T,S" strings. plot_topology_grid() and summarize() look results up by
(T, S) tuples, so they must be converted back, as floats (not strings,
not ints) to match T_values / S_values exactly.

# Part 2: the new c1 option in sweep_swarm() -- default unchanged, c1=0 differs
python3 -c "
from sweep_swarm import sweep_swarm
print(sweep_swarm('scale_free', n=200, generations=100, T_values=[1.5], S_values=[0.0], R=1, P=0, num_realizations=10, seed=1, tail=10))
print(sweep_swarm('scale_free', n=200, generations=100, T_values=[1.5], S_values=[0.0], R=1, P=0, num_realizations=10, seed=1, tail=10, c1=0.0))
"

Expected output (about 1 second):
{(1.5, 0.0): 0.1736}
{(1.5, 0.0): 0.68625}

Why: the first line must match the T=1.5, S=0.0 cell in
test_sweep_swarm.txt (0.17) -- proves adding the c1 option didn't change
the default behaviour. The second line switches off the personal-best
pull. If the two lines were identical, c1 isn't actually reaching
next_position().
